## 核心任务

创建一张高复杂度、代码原生、接近写实旅游海报质感的富士山 SVG 风景插画。

最终文件名：

```text
fuji.svg
```

建议画布：

```xml
viewBox="0 0 1600 1000"
```

画面必须包含：

- 冬季积雪覆盖的富士山
- 多层云海与山腰雾气
- 高空薄云和远处大气层
- 富士山脚下的城市远景
- 城市建筑、道路、窗户和灯光
- 湖面或湿润地表
- 富士山、云层、太阳和城市灯光的反射
- 清晨日出或黄金时刻光照
- 左暖右冷的方向性光照变化
- 山体岩层、雪沟、雪舌、山脊和坡面明暗
- 前景树林、岸线和水面波纹
- 明确的大气透视和远近层次

整体应明显比普通扁平插画复杂，但仍保留高质量矢量插画特征。不得生成儿童卡通、简单几何拼贴、低多边形或纯图标风格。

## 构图要求

- 画布比例约为 `16:10`。
- 富士山位于画面中部偏上。
- 山峰应自然且略微不对称。
- 不得将山峰画成简单等腰三角形。
- 山脚应被云海、薄雾和城市局部遮挡。
- 左侧低角度太阳提供暖色主光。
- 山体右侧和云底进入冷色阴影。
- 湖面约占画面下方 `25%–35%`。
- 城市位于山脚和岸线之间，不得漂浮。
- 前景使用深色树林、岸线或湿地增强景深。
- 画面视觉焦点必须是雪峰。
- 城市细节丰富，但不得抢过富士山主体。
- 避免完全左右对称。

## 富士山细节

富士山必须由大量有意义的矢量结构组成，包括：

- 自然、连续、略微不对称的山顶轮廓
- 左右高度不同的雪线
- 多块互相咬合的积雪面
- 狭长雪沟和积雪舌
- 裸露岩层和山体暗面
- 多条自然山脊和侵蚀纹理
- 不同尺度的坡面明暗变化
- 山顶附近较清晰、较细密的纹理
- 山脚附近受空气透视影响而柔化的细节
- 左侧暖色受光面
- 右侧冷色背光面
- 暖白、浅金、浅粉色积雪高光
- 浅蓝灰、紫蓝色积雪阴影

不得使用大量无规律的随机尖角、锯齿或互相穿透的山体面。

## 云海与大气

云海是主要视觉内容之一，必须认真构建。

至少包含：

- 后景云层
- 中景云层
- 前景云层
- 高空薄云
- 山腰云带
- 山脚云海
- 地平线薄雾
- 山体和城市之间的大气遮蔽层

要求：

- 主要使用自然的贝塞尔曲线构成云体。
- 不得仅靠规则圆形或椭圆机械堆叠。
- 云顶使用暖色阳光高光。
- 云底具有蓝紫色体积阴影。
- 远处云层更小、更淡、更偏冷。
- 近处云层轮廓更清晰、对比更强。
- 部分云层应自然遮挡山脚和城市。
- 云层之间必须存在明确的深度差异。
- 不得用一个巨大模糊形状冒充整片云海。
- 不得用铺满画布的 `feTurbulence` 冒充全部细节。
- 避免对数百个微小元素分别使用高成本模糊滤镜。

## 城市远景

城市不能只是少量矩形，至少应表现：

- 高低不同的住宅
- 酒店或较高建筑
- 商业建筑
- 仓库或低矮工业建筑
- 不同形式的屋顶
- 道路
- 桥梁或岸边通道
- 护栏
- 街灯
- 电线杆或其他基础设施
- 大小和亮度不同的窗户
- 少量克制的暖黄色灯光

要求：

- 建筑必须服从地形和地平线。
- 不得随机漂浮。
- 不得大面积互相穿透。
- 远处建筑颜色更淡、对比更低、细节更少。
- 近处建筑细节相对丰富。
- 窗户的位置、尺寸和亮度不能完全一致。
- 城市整体应受到晨光和空气透视影响。
- 城市不得抢过富士山主体。

## 湖面与倒影

湖面必须具有真实的层次变化。

要求：

- 富士山倒影应根据水平线正确进行几何翻转。
- 倒影不得只是复制山体后统一降低透明度。
- 倒影必须具有颜色偏移、亮度衰减和局部缺失。
- 使用裁剪、遮罩、分段图形或波纹破坏倒影完整性。
- 云层应具有较柔和的反射。
- 太阳应具有方向明确的纵向或碎片化光带。
- 城市灯光应具有短小且不规则的反射。
- 远处波纹较细、较密。
- 近处波纹较宽、较明显。
- 波纹主要沿水平方向展开。
- 倒影必须弱于真实主体。
- 不得出现上下方向错误的倒影。

## 光照与颜色系统

在 `<defs>` 中建立可复用、统一的光照与颜色系统，至少包括：

- 天空纵向主渐变
- 地平线暖光渐变
- 太阳径向渐变
- 山体受光渐变
- 山体冷阴影渐变
- 雪面暖光渐变
- 雪面冷阴影渐变
- 云顶高光渐变
- 云底阴影渐变
- 湖面基础渐变
- 湖面反射渐变
- 城市空气透视渐变
- 前景树林渐变

总体色彩关系：

- 天空上方：冷蓝、蓝紫
- 地平线：浅橙、桃粉、淡金
- 山体亮面：暖灰蓝、浅粉紫
- 山体阴影：靛蓝、深蓝灰
- 雪面高光：暖白、浅金白
- 雪面阴影：浅蓝、紫灰
- 城市灯光：克制的暖黄
- 前景：深蓝绿、深靛色

不要为每个微小元素分别创建独立渐变。应通过有限且可复用的渐变、遮罩、滤镜和图层建立统一视觉体系。

## SVG 图层结构

最终 SVG 必须具有语义清晰的图层，至少包含以下分组：

```xml
<g id="background-sky">
<g id="sun-and-glow">
<g id="high-clouds">
<g id="distant-atmosphere">
<g id="mount-fuji-base">
<g id="mount-fuji-snow">
<g id="mount-fuji-ridges">
<g id="mount-fuji-light">
<g id="cloud-sea-back">
<g id="cloud-sea-middle">
<g id="cloud-sea-front">
<g id="distant-city">
<g id="city-lights">
<g id="shoreline">
<g id="lake">
<g id="reflections">
<g id="water-ripples">
<g id="foreground-forest">
<g id="final-atmosphere">
```

可以增加更多子图层。

要求：

- 重要图层添加简短注释。
- `id` 必须具有语义。
- 不要使用无意义的随机字符串作为图层名称。
- 不要把所有内容塞入一个超长 `<path>`。
- 不要创建无意义的深层嵌套。

## 行数与复杂度要求

最终 `fuji.svg` 必须满足：

- 物理行数至少 `3000` 行。
- 建议控制在 `3200–5000` 行。
- 至少 `2800` 行为非空、非纯注释内容。
- 每个主要 SVG 元素单独占一行。
- 不得故意将同一元素的每个属性拆成多行凑行数。
- 不得使用大量空行凑行数。
- 不得使用无意义注释或重复元数据凑行数。
- 不得使用不可见元素凑行数。
- 不得使用画布外元素凑行数。
- 不得使用 `opacity="0"`、`display="none"` 或极小不可见元素凑复杂度。
- 不得机械复制完全相同的元素凑数量。
- 重复对象必须在位置、尺寸、轮廓、颜色、透明度或细节方面具有合理变化。
- 所有生成细节必须对最终画面产生可见作用。

细节应真实分布于：

- 天空和大气
- 高空薄云
- 多层云海
- 富士山坡面
- 雪面和雪沟
- 山脊和岩层
- 城市建筑和屋顶
- 窗户和灯光
- 道路与基础设施
- 树林和前景
- 湖面反射
- 水面波纹
- 光斑和空气透视

不要为了达到元素数量而破坏整体构图。

## 禁止内容

最终 SVG 不得包含：

- `<image>`
- `<foreignObject>`
- Base64
- `data:image`
- PNG、JPEG、WebP、GIF、AVIF 或其他位图
- 外部 URL
- 远程字体
- 外部脚本
- 浏览器运行时图形生成逻辑
- 在线生成服务产生的嵌入内容
- 位图自动描摹结果
- 依赖服务器才能显示的资源

最终 SVG 必须静态、独立、自包含，并可直接在现代 Chrome、Safari 和 Firefox 中打开。

## Python 生成器

创建：

```text
generate_fuji.py
```

要求：

- 使用 Python 生成最终 SVG。
- 优先使用 Python 标准库。
- 不依赖网络。
- 使用固定随机种子：

```python
20260629
```

- 多次运行必须生成一致内容。
- 按语义图层逐步生成 SVG。
- 使用辅助函数生成云层、山体纹理、建筑、窗户、树木、反射和水纹。
- 不要在 Python 中硬编码一个完整的三千行巨大 SVG 字符串。
- 坐标通常保留不超过两位小数。
- 避免无意义的长小数。
- 对坐标范围进行基本限制。
- 生成完成后输出文件行数、文件大小和元素数量统计。

删除生成脚本后，最终 `fuji.svg` 仍必须能够独立显示。

## SVG 验证器

创建：

```text
validate_svg.py
```

至少检查：

1. `fuji.svg` 存在。
2. 文件为有效 UTF-8。
3. XML 可以解析。
4. 根元素是 `<svg>`。
5. 存在有效的 `viewBox`。
6. 总行数不少于 `3000`。
7. 非空非注释行数不少于 `2800`。
8. SVG 元素总数达到合理复杂度。
9. 所有要求的关键图层存在。
10. 不存在 `<image>`。
11. 不存在 `<foreignObject>`。
12. 不存在 Base64。
13. 不存在 `data:image`。
14. 不存在外部 URL。
15. 不存在大量透明度为 `0` 的元素。
16. 不存在明显位于画布外的大批凑数元素。
17. 所有 `url(#...)` 引用均能找到对应定义。
18. 所有 `<use>` 引用均能找到对应元素。
19. 所有标签正确闭合。
20. 文件大小处于合理范围。
21. 主要图层中包含可见元素。
22. 输出不同 SVG 元素类型的数量统计。

验证失败时必须返回非零退出码。

不得通过降低验证标准来让作品显示为通过。

## 渲染与视觉检查

将最终 SVG 实际渲染为：

```text
preview.png
```

预览尺寸至少为：

```text
1600 × 1000
```

使用当前环境已有的本地工具，例如：

- `rsvg-convert`
- `magick`
- `convert`
- `inkscape`
- `cairosvg`
- 本地浏览器截图

不得调用在线服务。

渲染后必须检查：

- 富士山是否完整显示。
- 山峰位置是否合理。
- 山峰轮廓是否过度对称。
- 云海是否错误遮挡全部山体。
- 倒影方向是否正确。
- 城市是否位于合理的山脚和地平线区域。
- 是否出现黑块、白块或巨大异常图形。
- 是否存在裁剪、遮罩或引用错误。
- 渐变和滤镜是否正常。
- 建筑、树木或云层是否漂浮。
- 是否存在明显机械重复。
- 水面反射是否弱于主体。
- 前景是否遮挡过多。
- 整体光源方向是否一致。
- 浏览器缩放时是否保持清晰。
- 渲染性能是否处于可接受范围。

必须至少完成两轮：

```text
生成 → 验证 → 渲染 → 检查 → 修改
```

不得将未经检查的第一版直接作为最终结果。
